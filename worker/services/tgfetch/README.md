# TGFetch

Сервис загрузки и индексации музыкальных треков из Telegram для Cold Orbit Radio.

## Назначение

TGFetch отвечает за получение аудиофайлов из Telegram-каналов, сохранение их в объектное хранилище и регистрацию треков в общей медиатеке радио.

Задача TGFetch — доставить трек из Telegram в хранилище и зарегистрировать его в системе.

# Основные обязанности

## 1. Получение сообщений

Сервис подписывается на указанные Telegram-каналы и получает новые сообщения.

Поддерживаемые типы:

* Audio
* Music
* Документы с аудиофайлами

Игнорируются:

* текстовые сообщения;
* изображения;
* видео;
* голосовые сообщения;
* стикеры.

---

## 2. Извлечение метаданных

Из Telegram извлекаются:

* Telegram File ID;
* Message ID;
* Channel ID;
* имя файла;
* размер файла;
* длительность;
* исполнитель;
* название трека.

Если часть данных отсутствует, сервис сохраняет то, что удалось получить.

---

## 3. Создание записи трека

После обнаружения нового аудио создаётся запись в БД.

Пример статусов:

```text
NEW
DOWNLOADING
UPLOADING
READY
FAILED
```

---

## 4. Скачивание файла

Файл загружается через MTProto.

Требования:

* поддержка больших файлов;
* возможность повторных попыток;
* ограничение числа одновременных загрузок.

---

## 5. Загрузка в объектное хранилище

После успешного скачивания файл отправляется в MinIO.

Структура хранения:

```text
tracks/
 ├── 2026/
 │   ├── 06/
 │   │   └── uuid.mp3
```

После успешной загрузки в БД сохраняется ссылка на объект.

---

## 6. Обновление статуса

После завершения обработки:

```text
READY
```

При ошибке:

```text
FAILED
```

# Технический долг

## Очередь загрузок

Текущее решение может скачивать файл сразу после получения сообщения.

Планируется выделение отдельной сущности DownloadJob.

Пример:

```text
Track
  |
  +-- DownloadJob
```

Поля:

```text
id
track_id
status
attempt
created_at
updated_at
last_error
```

Статусы:

```text
PENDING
RUNNING
RETRY
FAILED
COMPLETED
```

Преимущества:

* многопоточность;
* управление количеством воркеров;
* повторные попытки;
* мониторинг;
* восстановление после рестарта.
